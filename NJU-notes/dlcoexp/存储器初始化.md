  

当需要初始化的 RAM 数据量较大的时候，可以使用文件来在系统启动时直接装入 RAM 数据。Verilog 提供了以下语句来将文件中的数据导入到 RAM中：

```matlab

initial

begin

$readmemh("D:/digital_logic/mem1.txt", ram, 0, 7);

end

```

以上内容可以替代前例中的 RAM 初始化部分，将 mem1.txt 中的数据导入到 ram 变量的第 0 单元至第 7 单元。请注意，这里 mem1.txt 可以存在任何不包含中文字符的目录下，但是在初始化语句中一定要给出此文件的绝对路径，否则仿真时将看不到初始化数据。

mem1.txt的内容和格式如下：

```txt

1 @0 0d

2 @1 82

3 @2 21

4 @3 03

5 @4 20

6 @5 ff

7 @6 50

8 @7 04

```

其中 @ 符号后为 ram 地址，随后是 16 进制的 ram 数据。在 verilog 中，\$readmemh 方法读取 16 进制数据，\$readmemb 方法读取 2 进制数据。

初始化存储器时可以选择存储器的部分单元进行初始化，其他单元不初始化。如，假设存储器 ram 有 8 个存储单元，下面的初始化表示只对存储器的0 5 号单元进行初始化，这也是可以的。

```matlab

initial

begin

$readmemh("D:/digital_logic/mem1.txt", ram, 0, 5);

end

```

  

假设存储器 ram 有 8 个存储单元，下面的初始化试图对存储器的 0 8 号单元，共9 个单元进行初始化，这是不可以的。

  

```matlab

initial

begin

$readmemh("D:/digital_logic/mem1.txt", ram, 0, 8);

end

```

  

对存储器进行初始化还有其他方式，我们会在以后的实验中继续介绍。

  

## 4.4 使用 IP核生成存储器

  

Vivado 提供了很多非常实用的 IP 核，IP 核是预先实现和测试过的模块，具有较高的可靠性。利用这些 IP 核可以很方便的实现复杂的设计。下面我们以设计一个存储器为例来介绍如何使用VivadoIP 核。

  

## 4. 4 .1 通过 IP 生成 RAM

  

在 Vivado 界面的左边 Flow Navigator 下的 Project Manager 里点击 IP Catalog界面右边会显示 IP 目录，搜索 RAM，可以找到 Block Memory Generator 如图4 6所示

  


  

点击 Block Memory Generator 可以进入如图 4 7界面对存储器进行详细配置。

  



i d 的存储模块 配置有较多选项，请务必清晰理解每个选项的含义，避免配置出不合理的结果。以下我们按照配置一个16个存储单元，每个存储单元 16bit（2Byte）的 RAM 为例进行说明。在图4 7中的基础配置中包含以下的重要选择项。

  

 Component Name: 决定了本 IP 模块的名称，后续实例化该模块时需要按此模块命名来实例化，这里我们使用了缺省名称blk\_mem\_gen\_0。

  

 Interface Type: 定义了存储模块的接口，即实例化之后该模块有哪些输入输出参数。Vivado 的存储模块支持 Native 的基本存储模块，即类似我们之前的 RAM 实现，以读写地址、写使能、写入数据、输出读数据及时钟这些接口调用存储模块，也可以使用标准的 AXI 总线接口调用存储。我们这里使用 Native 接口，后续在计算机系统中可能会采用总线调用方式。接口选择后可以点开左边的模块接口示例，观察该模块有哪些接口。当配置不同时，模块的接口及接口的位宽都有可能改变。

  

 Memory Type：支持单口 RAM，真双口 RAM，单口 ROM 及双口 ROM 的存储模式。不同存储模式提供不同数量的读写端口。

  

 Write Enable：写使能，可以采用一位写使能对整个单元进行写入，也可以根据需要写入部分数据。例如，我们可以勾选 Byte Write Enable 选项，让数据每 8 个 bit 拥有单个写使能。这样，我们的 16bit RAM 就会有两位的写使能 wea[1:0]。当 wea[0] 为 1 时对低 8bit 写入，wea[1] 为 1 时对高 8 比特写入，如果要对 16bit 写入则可以设置 wea[1:0]=2’b11。这种 Byte Write 将来在实现RISC-V 存储器中对32位的Word进行单字节操作的时候非常有用。

  


  

 存储器大小：主要通过 Read/Write Width 来配置每个单元的 bit 数，我们这里统一配置为 16 个 bit。通过 Read/Write Depth 来配置单元数量，这里选择16 个存储单元，即读写地址是 4 位的。单元数量可以是 2 的幂次，也可以自行选择以减小存储的小孩。

  

 操作模式及使能方式：用于配置是写优先还是读优先，以及片选使能端的方式，可以使用缺省设置。

  

 输出寄存器：配置是否需要在输出端进行寄存，如果选择了输出寄存，可以观察最后的 Summary 会发现读取所需的周期数会由原来的 1 个周期变为个周期，这主要是输出寄存器需要一个周期的时延。所以，我们这里选择不要输出寄存，即一个周期就可以得到数据，这在未来的 CPU 读取时序设计中非常重要。

  

 其他配置：可以使用缺省值。

  

在图4 9中的其他属性配置里最重要的是初始化文件的选择。在 Vivado中，可以使用 Xilinx 自己专用的 COE 文件格式来对存储进行初始化，COE 文件也是用文本方式来规定存储的内容。例如，我们可以用如下方式来设置 COE文件：

  

```txt

; .COE file with hex coefficients

memory_initialization_radix=16;

memory_initialization_vector=

0000,0001,0002,0003,

0004,0005,0006,0007,

0008,0009,000A,000B,

000C,000D,000E,000F;

```

  

其中以; 号开头的行为注释，memory\_initialization\_radix 规定了存储初始化文件使用 16 进制方式表示。memory\_initialization\_vector 规定了所有单元的内容，存储单元以逗号分开，最后以分号结束。

  

  

在图4 10中的 IP 核配置结果中显示了该存储模块使用了多少 BRAM资源，以及读取需要多少时钟周期。选择 OK 后，在下一步的对话框中点击 Generate 。等生成完毕，该 IP 核就可以使用了，我们可以在 Sources 里的列表中观察到对应的模块，如图4 11所示。在完成配置之后，如果需要修改 IP配置也可以双击Source中对应的IP 核进行修改。

  

在调用IP 核时，可以按一般的模块实例化方式进行实例化，如：

  

```prolog

blk_mem_gen_0 myram(.addra(SW[15:12]), clka(clk), dina({8'h0,SW[7:0]}), douta(LED[15:0]), ena(1'b1), wea(SW[11:10]));

```

  

将该IP 核实例化，并连接到开发板的各个输入输出上去。
