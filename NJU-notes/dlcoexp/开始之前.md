在写下第一行代码前，请在脑海中完成这个切换：

- **C++（你熟悉的）：** 软件开发。代码是**顺序执行**的，跑在现有的 CPU 电路里，操作的是寄存器和内存。
    
- **Verilog（即将接触）：** 硬件电路描述。你的代码是在**描绘电路结构**。所有的 always 块、所有的逻辑门和连线在物理空间上都是**同时工作（并行执行）**的。你的代码写完、编译（综合）后，会被翻译成逻辑网表，最终在 FPGA 的查找表（LUT）和触发器上变成**真实的物理电路**。

## 一、 新建工程（Create Project）

打开 Vivado 界面，点击 **Create Project** [2]：

1. **Project Name (工程命名)：**
    
    - **原则：** 英文路径，无空格，无中文（例如 E:/NJU_DLCO/lab0）。
        
    - 勾选 Create project subdirectory（为工程建立子文件夹，保证整洁）。
        
2. **Project Type (工程类型)：**
    
    - 选择 **RTL Project**（RTL 代表寄存器传输级，这是标准的硬件开发工程）。
        
    - 勾选 Do not specify sources at this time（后续我们再手动创建代码文件，这样最清晰）。
        
3. **Default Part (选择芯片型号 - 极其关键 ⚠️)：**
    
    - 你们实验使用的是 **Digilent Nexys A7-100T** 开发板，其核心芯片属于 Xilinx Artix-7 系列。
        
    - 不要在列表中盲目寻找板子。请在 **Search** 框中直接输入芯片的具体型号：  
        👉 **xc7a100tcsg324-1**
        
    - 在过滤出的单行结果中双击选中它。（注：选择错误的型号会导致你的管脚约束完全无法匹配，最后无法烧录到物理板子上！）
        
4. 点击 **Finish**，进入 Vivado 主界面。

## 二、 编写 RTL 代码（Design Sources）

进入主界面后，你会看到左侧的 **Sources** 窗口和 **Flow Navigator** 导航栏。

1. **创建/添加 Verilog 文件：**
    
    - 在左侧 Sources 窗口中，点击 **+** 按钮（或右键选择 Add Sources...）。
        
    - 选择 **Add or create design sources**，点击 Next。
        
    - 点击 **Create File**，File type 选择 **Verilog**，File name 输入模块名（例如 top 或 mux21，代表一个2选1选择器）。
        
    - 点击 Finish，在弹出的 Define Module 界面可以直接点击 OK（我们在代码中手动定义输入输出接口，更不容易出错）。
        
2. **编写你的第一个电路（以简单的 2选1 选择器为例）：**  
    在主编辑区双击打开刚刚新建的 .v 文件，写下如下代码：
    
    codeVerilog
    
    ```
    module mux21(
        input  wire a,      // 输入信号 A
        input  wire b,      // 输入信号 B
        input  wire s,      // 选择控制信号 S
        output wire y       // 输出信号 Y
    );
        // 当 s 为 1 时输出 b，当 s 为 0 时输出 a
        assign y = (s == 1'b1) ? b : a;
    
    endmodule
    ```
    
    - Ctrl + S 保存。若代码有语法错误，左侧 Sources 树状图中的文件图标上会出现红色的 x，并在底部的 Messages 窗口显示错误行号。

## 三、 仿真验证（Behavioral Simulation）

**在将电路烧录到物理板子之前，必须先进行仿真。这是硬件开发的黄金铁律。** 物理烧录一次需要几分钟，而仿真只需要几秒钟。

1. **创建 Testbench（仿真测试激励文件）：**
    
    - 点击 Add Sources -> 选择 **Add or create simulation sources** -> Next。
        
    - 点击 Create File，命名为 tb_mux21。
        
2. **编写仿真激励：**  
    打开 tb_mux21.v，编写以下给输入信号“灌入”测试波形的代码：
    
    codeVerilog
    
    ```
    `timescale 1ns / 1ps  // 时间单位 1ns，时间精度 1ps
    
    module tb_mux21();
        // 1. 声明给被测模块输入的变量（仿真中必须用 reg 类型驱动输入）
        reg  a_in;
        reg  b_in;
        reg  s_in;
        // 2. 声明被测模块输出的观察变量
        wire y_out;
    
        // 3. 例化（Instantiate）被测模块，将仿真信号连线到电路引脚上
        mux21 u_mux21 (
            .a(a_in),
            .b(b_in),
            .s(s_in),
            .y(y_out)
        );
    
        // 4. 产生测试波形
        initial begin
            // 初始化信号
            a_in = 0; b_in = 0; s_in = 0; #10; // 维持 10ns
            a_in = 1; b_in = 0; s_in = 0; #10; // s=0，应该输出 a 的值（1）
            a_in = 1; b_in = 0; s_in = 1; #10; // s=1，应该输出 b 的值（0）
            a_in = 1; b_in = 1; s_in = 1; #10; // s=1，应该输出 b 的值（1）
            $finish; // 结束仿真
        end
    endmodule
    ```
    
3. **运行仿真：**
    
    - 在左侧 Flow Navigator 栏中，找到 **Simulation** -> 点击 **Run Simulation** -> 选择 **Run Behavioral Simulation**。
        
    - Vivado 会自动打开仿真波形界面（Waveform Window）。
        
    - 点击上方的 **Zoom Fit（快捷键 F）** 自适应缩放，你就能清晰地看到波形：观察当 s 改变时，y 的输出是否符合你的预期。

## 四、 物理约束管脚（Constraints .xdc）

代码在仿真里跑通了，但 FPGA 怎么知道你的输入信号 a 应该对应板子上的哪个拨码开关？输出 y 对应哪个 LED 灯？这需要**物理管脚约束文件**。

1. **创建约束文件：**
    
    - 点击 Add Sources -> 选择 **Add or create constraints** -> Next。
        
    - 点击 Create File，建立一个名为 nexys_a7 的 .xdc 文件（也可以直接添加课程网站提供的初始 XDC 约束模板）。
        
2. **编写管脚映射关系：**  
    打开 nexys_a7.xdc，加入如下约束（这些硬件管脚编号来自 Nexys A7 的官方手册）：
    
    codeText
    
    ```
    ## 拨码开关 (Switches)
    set_property -dict { PACKAGE_PIN J15   IOSTANDARD LVCMOS33 } [get_ports { a }]; # SW[0] 对应输入 a
    set_property -dict { PACKAGE_PIN L16   IOSTANDARD LVCMOS33 } [get_ports { b }]; # SW[1] 对应输入 b
    set_property -dict { PACKAGE_PIN M13   IOSTANDARD LVCMOS33 } [get_ports { s }]; # SW[2] 对应选择控制 s
    
    ## LED 灯 (LEDs)
    set_property -dict { PACKAGE_PIN H17   IOSTANDARD LVCMOS33 } [get_ports { y }]; # LED[0] 对应输出 y
    ```
    
    - 注：PACKAGE_PIN 物理引脚编号，IOSTANDARD LVCMOS33 表示使用 3.3V 的低压互补金属氧化物半导体电平。

## 五、 从代码到电路（Synthesis -> Implementation -> Bitstream）

这是 Vivado 的自动化核心，在左侧的 Flow Navigator 栏，你只需要顺着往下点这三步：

1. **Run Synthesis（综合）：**
    
    - 点击后，Vivado 会将你的 Verilog 代码翻译成由查找表（LUT）、触发器（DFF）等基础逻辑单元构成的网表电路。
        
2. **Run Implementation（实现/布局布线）：**
    
    - 点击后，Vivado 会把综合出来的逻辑单元，具体分配到 FPGA 芯片物理芯片上具体的 LUT 硅片位置上，并计算它们之间的金属走线长度和时延，确保满足时序要求。
        
3. **Generate Bitstream（生成比特流）：**
    
    - 点击后，系统会生成一个 .bit 后缀的二进制文件。这个文件里包含了所有开关连线和查找表配置的信息，可以直接烧写进 FPGA。
        
    - （省时间秘籍 💡：你可以直接点击最底部的 Generate Bitstream，Vivado 会自动检测前面两步是否完成，若没有完成，它会自动按顺序跑完 Synthesis 和 Implementation，一条龙生成比特流，你只需要点一次并等待即可。）

## 六、 物理烧录验证（Program Device）

生成比特流后：

1. **连接硬件：** 用 Micro-USB 数据线，一头连在 Nexys A7 板子的 **PROG** 接口（注意不是 UART 接口），另一头插在电脑的 USB 口上。拨动开发板上的红色电源开关（POWER）。
    
2. **打开硬件管理器：**
    
    - 在左侧 Flow Navigator 最底部，点击 **Open Hardware Manager** [2] -> 选择 **Open Target** -> 选择 **Auto Connect**。
        
    - 如果驱动安装正确，Vivado 会在顶部显示连接到了 xc7a100t_0 芯片。
        
3. **烧写电路：**
    
    - 右键点击识别出来的芯片 xc7a100t_0，选择 **Program Device...**。
        
    - 系统会自动选中你刚刚生成的 .bit 文件，点击 **Program**。
        
    - 板子上的 **BUSY（或 DONE）** 黄色指示灯会亮起，代表烧录成功！
        
4. **板级调试：**
    
    - 现在去拨动开发板最右侧的三个拨码开关：SW0（a）、SW1（b）、SW2（s）。
        
    - 当 SW2 拨到下方时，LED0 的亮灭随 SW0 同步；当 SW2 拨到上方时，LED0 的亮灭随 SW1 同步。你手写的物理电路正在物理空间上实时运行！

## 七、 ⚠️ 南大 DLCO 实验避坑与生存守则

1. **路径与命名绝不使用中文与空格。** 这是造成 90% Vivado 莫名其妙编译失败的原因。
    
2. **仿真和例化时注意信号类型：**
    
    - 被例化的电路输入引脚，在 Testbench 中必须声明为 **reg** 变量（因为需要仿真时序来给它主动赋值）。
        
    - 被例化的电路输出引脚，在 Testbench 中必须声明为 **wire**（因为它是被动接收电路输出的）。
        
3. **OJ（在线测评系统）的特殊要求：**
    
    - 南大 DLCO 的在线 OJ（如实验一的在线测评）通常只需要你提交核心设计 .v 源码。
        
    - **⚠️ 切记：提交到 OJ 的顶层模块（Top Module）名称、接口输入输出信号名，必须与题目要求完全一致，一个字母大小写都不能错**，否则 OJ 自动测试平台会因为无法识别引脚而判定为 0 分。
        
4. **不要在 always 块里对同一个变量多次赋值：**
    
    - Verilog 中一个变量（如寄存器 reg）只能被**一个** always 块（一个进程）驱动。如果你在两个不同的 always 块里对同一个 reg 赋值，编译时会报 Multi-driven source（多驱动源错误），代表电路发生了短路，这是物理上无法实现的。
