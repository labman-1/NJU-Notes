# 1-1：C 语言中的 struct 和 union 关键字都是什么含义，寄存器结构体的参考实现为什么把部分 struct 改成了 union？
##### (1) `struct` 与 `union` 的本质区别（内存布局）
* **`struct`（结构体）—— 顺序物理排列**：
  * 每个成员拥有独立的内存空间。
  * 结构体的大小 $\ge$ 所有成员大小之和（受内存对齐影响）。成员在内存中的物理偏移量（Offset）是顺次累加的。
* **`union`（共用体）—— 重叠物理共享**：
  * 所有成员**共享完全相同的物理起始地址（Offset = 0）**。
  * 共用体的大小等于其最大成员的大小。修改其中任意一个成员的值，会**直接且同步改变**其他成员对应的二进制位。

##### (2) 为什么必须把原本的 `struct` 改成 `union`？
在物理 CPU 硅片中，`EAX`、`AX`、`AH`、`AL` **从来不是独立的 4 个寄存器**，而是同一排 32 个物理触发器（Flip-Flop）的不同访问视口（View）：
* 如果像原框架代码那样全写成 `struct`，在内存中 `_32`、`_16` 和 `_8[2]` 是**顺次排队**的（占 $4+2+2=8$ 字节），修改 `EAX` 的值绝对影响不到 `AL`，这就完全违背了 x86 的硬件规范。
* **改用 `union` 的必然性**：
  * **内层 `union`**：让 32 位整数 `_32`、16 位整数 `_16`、以及 2 个字节的数组 `_8[2]` 物理重叠在同一块 4 字节内存中。修改 `_32` 时，`_8[0]`（小端序低字节）自动对应 `AL`，`_8[1]` 自动对应 `AH`。
  * **外层 `union`**：让 `gpr[8]` 数组与具名结构体 `struct { eax, ecx ... }` 物理重叠在同一块 32 字节内存中，使得 `cpu.eax` 与 `cpu.gpr[0]._32` 物理上指代同一块内存。
