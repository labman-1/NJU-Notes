# 1-1：C 语言中的 struct 和 union 关键字都是什么含义，寄存器结构体的参考实现为什么把部分 struct 改成了 union？
##### (1) `struct` 与 `union` 的本质区别（内存布局）
* **`struct`（结构体）—— 顺序物理排列**：
  * 每个成员拥有独立的内存空间。
  * 结构体的大小 $\ge$ 所有成员大小之和（受内存对齐影响）。成员在内存中的物理偏移量（Offset）是顺次累加的。
* **`union`（共用体）—— 重叠物理共享**：
  * 所有成员**共享完全相同的物理起始地址（Offset = 0）**。
  * 共用体的大小等于其最大成员的大小。修改其中任意一个成员的值，会**直接且同步改变**其他成员对应的二进制位。

##### (2) 为什么必须把原本的 `struct` 改成 `union`？
在物理 CPU 硅片中，`EAX`、`AX`、`AH`、`AL` 不是独立的 4 个寄存器，而是同一排 32 个物理触发器（Flip-Flop）的不同访问视口：
* 如果像原框架代码那样全写成 `struct`，在内存中 `_32`、`_16` 和 `_8[2]` 是**顺次排队**的（占 $4+2+2=8$ 字节），修改 `EAX` 的值绝对影响不到 `AL`，这就完全违背了 x86 的硬件规范。
* 为什么必须改为`union`：
  * **内层 `union`**：让 32 位整数 `_32`、16 位整数 `_16`、以及 2 个字节的数组 `_8[2]` 物理重叠在同一块 4 字节内存中。修改 `_32` 时，`_8[0]`（小端序低字节）自动对应 `AL`，`_8[1]` 自动对应 `AH`。
  * **外层 `union`**：让 `gpr[8]` 数组与具名结构体 `struct { eax, ecx ... }` 物理重叠在同一块 32 字节内存中，使得 `cpu.eax` 与 `cpu.gpr[0]._32` 物理上指代同一块内存。

## 1. 针对“阶码上溢产生 $\pm \infty$”的情形：加法、乘法均能找到

* **加法（同号大数相加）**：
  - **正无穷 ($+\infty$)**：
    取两个接近最大单精度正浮点数的规格化数：
    $a = 3.0 \times 10^{38}$ (`0x7EFFFFFF`)，$b = 3.0 \times 10^{38}$ (`0x7EFFFFFF`)。
    $a + b = 6.0 \times 10^{38}$，超过单精度最大可表示上限（约 $3.4028 \times 10^{38}$），阶码达到 $255$，输出 **`+inf` (`0x7F800000`)**。
  - **负无穷 ($-\infty$)**：
    $a = -3.0 \times 10^{38}$ (`0xFEFFFFFF`)，$b = -3.0 \times 10^{38}$ (`0xFEFFFFFF`)。
    $a + b = -6.0 \times 10^{38}$，负向超出下限，输出 **`-inf` (`0xFF800000`)**。

* **乘法（大数相乘阶码相加）**：
  - **正无穷 ($+\infty$)**：
    $a = 2.0 \times 10^{20}$ ，$b = 2.0 \times 10^{20}$ 。
    $a \times b = 4.0 \times 10^{40}$，指数相加远超 $127$，输出 **`+inf` (`0x7F800000`)**。
  - **负无穷 ($-\infty$)**：
    $a = -2.0 \times 10^{20}$ ，$b = 2.0 \times 10^{20}$ 。
    $a \times b = -4.0 \times 10^{40}$，异号相乘溢出，输出 **`-inf` (`0xFF800000`)**。

## 2. 针对“阶码下溢产生 $\pm 0$”的情形：乘法能找到，加法找不到

乘法：能够找到
- **正零 ($+0$)**：
  取两个非零的极小正非规格化数：
  $a = 2^{-140}$ (`0x00000200`)，$b = 2^{-140}$ (`0x00000200`)。
  $a \times b = 2^{-280}$。指数远小于单精度最小非规格化数能表示的极限（$2^{-149}$），临时阶码下溢，在规格化右规与舍入后有效位全被移出，输出 **`+0` (`0x00000000`)**。
- **负零 ($-0$)**：
  $a = -2^{-140}$ (`0x80000200`)，$b = 2^{-140}$ (`0x00000200`)。
  乘积为 $-2^{-280}$，下溢且符号为负，输出 **`-0` (`0x80000000`)**。

加法分析：找不到
理由如下：
1. **同号数相加**：$|a + b| \ge \max(|a|, |b|)$。数值绝对值只会变大或不变，绝不可能产生比输入还要小的下溢。
2. **异号数相加（即减法 $a - b$）**：
   - 若 $a = b$，其差值精确为零，这是正常的相互抵消，属于数值有效相消，并非“阶码下溢”导致的舍入为零。
   - 若 $a \ne b$：
    任何两个不同的浮点数做相减，其真实差值的绝对值必然大于等于 $2^{-149}$，这个差值必定能够被 IEEE 754 的非规格化数精确表示，不可能因下溢被舍入为 0。
   - 综上所述，浮点加法不可能发生“非零结果因阶码下溢变成 $\pm 0$”的现象。
