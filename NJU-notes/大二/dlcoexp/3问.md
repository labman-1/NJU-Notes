### 问题一：Vivado 的 Sources 下几个文件夹的含义、用途、区别

在 Vivado 中，所有的文件被归类在四个核心文件夹中，它们分工明确，代表了电路设计的不同阶段：

| 文件夹名称 | 核心含义 | 用途与物理图像 | 区别 |
| :--- | :--- | :--- | :--- |
| **Design Sources**<br>（设计源文件） | **真正的物理电路** | 存放你写的 Verilog 源码（如 `.v` 文件）。**只有这里的代码，才会被综合成实实在在的、FPGA 芯片里的逻辑门和物理导线。** | 决定了芯片“长成什么样子”。 |
| **Constraints**<br>（约束文件） | **物理世界的接口桥梁** | 存放物理引脚约束文件（如 `.xdc`）。它将你代码里的逻辑信号（如 `SW[0]`）映射到开发板上真实的铜脚（如 `J15`）上。 | 决定了你的电路“如何与外接硬件连通”。 |
| **Simulation Sources**<br>（仿真源文件） | **虚拟实验室的试剂** | 存放测试激励文件（Testbench，如 `tb_mux21.v`）。它只在电脑软件里跑，模拟电路波形。 | **绝不会**变成物理电路落盘。 |
| **Utility Sources**<br>（工具源文件） | **编译脚本与辅助工具** | 存放编译前后的脚本、设计约束检查（DRC）的配置等。 | 属于后台辅助工具，日常实验可以直接忽略。 |

### 问题二：为什么 Vivado 出来的是 `exp1` / `exp2`，而格雷码还是原名？

这是 Verilog 与 C++ 的一个非常有趣的**底层差异**：

*   **Verilog 编译器的法则是：以“模块名”（Module Name）为尊，而不是文件名（File Name）。**
*   **解释：**
    *   在 `2bitsSelector.v` 文件的内部，你写的是 `module exp1( ... )`。Vivado 的编译器在扫描代码时，抓取的是你的**模块名 `exp1`**，因此它在树状图里显示 `exp1`，并在括号里备注源自 `(2bitsSelector.v)`。
    *   同理，在 `PreferenceCoder.v` 内部，你写的是 `module exp2(...)`。所以它显示的是 **`exp2 (PreferenceCoder.v)`**。此外，它在下方自动缩进显示了你例化的子模块 `u_bcd7seg : bcd7seg`，展现了层级关系。
    *   而在 `graycode.v` 内部，你写的恰好就是 `module graycode(...)`。由于模块名和文件名一模一样，所以它显示 **`graycode (graycode.v)`**。

> **💡 行业好习惯：** 
> 以后我们在设计电路时，**强烈建议把“文件名”和文件内的“模块名”保持 100% 一致**（例如把文件名也改成 `exp1.v` 和 `exp2.v`），这能极大减少后续管理大型项目的认知混乱。

### 问题三：`top_lab01.v` 在哪里？怎么写？与子程序有什么区别？

#### 1. `top_lab01.v` 在哪里？是要新建吗？
**是的，你现在需要在 VSCode 里手动新建它！**
*   **操作方法：** 
    1.  切换到 VSCode，点击你的 `lab01` 文件夹旁边的“新建文件”图标，创建一个名为 **`top_lab01.v`** 的文件。
    2.  双击打开它，把我在上上轮为你写好的 **`top_lab01.v` 的完整代码** 复制进去并保存（`Ctrl + S`）。
    3.  回到 Vivado 界面，点击 `Sources` 面板上的 **`+`** -> 选择 `Add or create design sources` -> 点击 `Add Files` -> 选中你刚刚在本地新建的 **`top_lab01.v`**（确保不要勾选 `Copy sources into project`）[2] -> 点击 Finish。
    4.  *此时，你会发现 Vivado 的 `Design Sources` 树状图瞬间重构：`top_lab01` 自动成为了大树的主干，而 `exp1`、`exp2`、`graycode` 全部自动缩进，成为了它的分支节点！*

#### 2. 顶层连线程序与之前的三段子程序有什么区别？
*   **子程序（独立芯片）：** 你之前写的 `exp1`、`graycode`、`exp2` 就像是散落在实验桌上的**三个独立功能的芯片**。它们本身不知道外界的开关（`SW`）和 LED 灯在哪里，也无法直接和物理世界对话。
*   **顶层连线程序（主板电路）：** `top_lab01.v` 是**整块大主板**。它是唯一一个直接和开发板硬件引脚（`SW`、`LED`、`AN`、`HEX`）连通的模块。
*   **它的工作：** 它在主板上挖了三个槽，把这三颗芯片插上去，并用铜线把开关的信号导进芯片的输入，再把芯片的输出导向 LED 灯和数码管。

#### 3. 为什么程序这么长？
*   **因为它包含了详尽的注释。** 如果我们把里面为了让你看懂而写的中文注释全部去掉，它其实**非常短**，只有大概 20 行：它只是定义了 16 个开关和 LED，声明了几个内部变量，然后做了三次 `u_` 开头的芯片实例化（物理连线）。
