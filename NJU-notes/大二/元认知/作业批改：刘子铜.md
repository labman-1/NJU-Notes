# 作业批改：刘子铜
> 当自己一无所知的时候采用读文档的形式来建立认知是低效的，因为写文档的人或已建立完整认知，或仅写出局部了解……这个时候应该先用ai产生一个整体的认识，明白可以用什么方法去做，再去文档中寻求具体的手段和资源
>

给这段话点个赞！不仅仅是因为策略，我觉得更重要的是，这种行为模式，才是在AI时代，人类认知增长和AI辅助的一种结合，相当于你在有一些外部参考（他人文档）的情况下，通过AI快速构建大致的知识体系（符合自己认知基础的），然后大量的外部参考，可以再次被AI辅助，精准的（效率比没有AI高太多）去补你自己的知识短板

## 1. 完成度判定
+ 状态：已完成
+ 依据：文档包含详细的时间线记录（9:30-18:14全程）、初步思考、阅读他人文档的笔记、需求明确、技术路径确定（Python+Yuque API+DeepSeek API+Web UI）、实践过程（S1-S5五个步骤）、成品截图、以及非常完整的反思环节（6个维度的结构化复盘）。系统已搭建完成并运行，能按关键词筛选文档并进行阅读优先级推荐。

## 2. 系统需求清单
+ 爬取语雀数据：获取团队知识库文档
+ 根据关键词进行结构化输入：按关键词筛选文档
+ 根据原则分析与概括：AI分析文档内容
+ 阅读优先级推荐：AI标注重点文档供亲自阅读，设置"与当前内容强相关"维度根据输入"目标"优先推荐
+ 提取重要信息：标题、核心问题、核心观点、关键方法、值得学习的地方、阅读价值【亮点】——分析维度设计简洁实用，"值得学习的地方"体现了对他人文档价值的主动挖掘
+ 不需要自动更新：手动启动即可，"开始工作之前分析一遍，上课之前分析一遍"
+ 简单网页UI：本地网页展示分析结果，点击题目可跳转阅读
+ 锻炼元认知能力：项目本身要详细记录以锻炼元认知【亮点】——把"记录过程"本身作为需求，体现了对元认知实践环境的理解
+ 学习AI agent知识：通过项目学习以便日后需求
+ 提升阅读他人文档的效率：核心实用目标

## 3. 搭建思路
作者分为认知、设计、执行三个阶段。认知阶段：先阅读全班同学的文档（做了详细笔记，标注重点文档用黄色高亮），了解各种技术路线和设计方案，产生逃避心理后重看重点文档；学习语雀API与token；向GPT喂入所有信息形成任务流程（Step1跑通API→Step2测试DeepSeek→Step3建立阅读价值评价标准→Step4做网页）。设计阶段：确定Python+Yuque API+DeepSeek API技术路径，犹豫了Dify但GPT建议自己了解API/token的实际应用。执行阶段：S1爬取文档+关键词筛选（复用成功案例）；S2安装openai包+购买DeepSeek API；S3写提示词（回去认真研读文档）；S4 vibe-coding搭建本地网页；S5根据测试数据迭代提示词。所用工具/平台：语雀API（团队token）、Python、DeepSeek API、GPT（方案规划）、Flask（本地网页）、PyCharm。

## 5. 元认知视角评估与鼓励
+ 思维过程暴露：非常充分。这是全班时间线记录最完整的作业——从9:30到18:14每个阶段都标注了时间，包括"吃饭！（12:03-12:26）"和"把vpn更新了一下（11:44）"这样的细节。反思环节按6个维度结构化展开（时间分配、认知阶段、实践阶段、调整思路、收获、未完成探索），每个维度都有具体分析和归因。
+ 亮点鼓励：
 1. 你的反思中有一个极其精准的自我诊断——"当自己一无所知的时候采用读文档的形式来建立认知是低效的，因为写文档的人或已建立完整认知，或仅写出局部了解……这个时候应该先用ai产生一个整体的认识，明白可以用什么方法去做，再去文档中寻求具体的手段和资源"。这个认知策略的调整不是理论上的，而是在实践中踩坑后的真实顿悟，是程序性元认知的典型表现。
 2. 你对自己的时间分配做了量化分析——"基本用了九个小时"，并区分了认知/设计/执行三个阶段的效率差异，指出"设计效率最高"而"实践阶段最应该节省的时间最长"。这种对自身认知资源分配的监控和评估非常成熟。
 3. 你坦诚记录了"前期长时间思考然后实践想要偷懒"的倾向，并归因到具体环节（格式规范不清楚、环境配置问题、PyCharm功能不了解）。不回避自己的弱点并具体定位，这比泛泛说"我不够努力"有价值得多。
+ 可提升处：阅读他人文档阶段产生了"逃避心理（太多了而且不完全了解）"，这里可以进一步分析：是信息过载导致的认知资源耗竭，还是不确定性导致的焦虑？区分这两种不同类型的"逃避"有助于选择不同的应对策略。
