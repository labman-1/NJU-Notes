# 作业批改：宋怡乐
挺好的，为什么

+ 一开始不理解这门课要做啥，但是你主动思考和行动去对齐信息了
+ 对Ai的输出有校验意识（复核Dify是否满足需求）
+ 自己动手注册了DS，不停留在思考，有了决策就一路开始实践，也不抗拒陌生的事物
+ 调用了前置经验（3000字足够反馈重要信息且能被人阅读）
+ 有了阶段性成果（一个可用的prompt）

接下来的需求自然就出现了

你发现A、B、C、D...同学的文档都很值得阅读，使用Prompt的方式，你需要

+ 复制文档内容给AI
+ 重复上述操作N次

你懒，能不能把这种事交给AI一并解决？

## 1. 完成度判定
+ 状态：已完成
+ 依据：使用Dify平台搭建了完整工作流（语雀插件抓取→DeepSeek分析→输出），编写了详细的元认知分析提示词，试运行成功并得到输出。有搭建过程记录和反思。

## 2. 系统需求清单
1. AI智能文档分析助手——分析课程文档的元认知特征
2. 分析维度包含：主旨大意概括、思维过程暴露程度、问题拆解能力、认知策略自觉性、监控与调整证据、反思深度与归因质量、外部反馈整合能力、元认知术语运用质量【亮点：8个维度全面覆盖元认知框架】
3. 综合诊断：元认知画像、认知失衡点识别、可迁移行动建议【亮点：从分析到诊断到行动建议的闭环】
4. 证据优先——所有评价必须引用文档原文作为依据
5. AI自我质疑——分析结束后反思自身分析质量【亮点：让AI也做元认知】
6. 成长导向而非打分——聚焦可改进方向和已有优势

## 3. 搭建思路
+ 平台选择：豆包推荐Dify→DeepSeek复核确认可行→百度搜索注册Dify。
+ 工作流：开始→语雀插件抓取文档→DeepSeek大模型分析→输出。
+ 语雀插件从Dify下载，群内找到token配置。
+ 自行注册DeepSeek获取API key（Dify免费额度不够用）。
+ 提示词编写：将自己对元认知的理解+课程介绍文档给DeepSeek，让其帮忙拟写3000字提示词，再粘贴进Dify调试。
+ 以自己的课前预习文档为蓝本试运行，若干调试后成功输出。

## 4. 技术评估：方案是否覆盖需求
| 需求 | 覆盖情况 |
| --- | --- |
| 文档抓取 | ✅ Dify语雀插件+token配置 |
| LLM分析 | ✅ DeepSeek API接入 |
| 8维度元认知分析 | ✅ 提示词完整覆盖 |
| 综合诊断 | ✅ 画像+失衡点+行动建议 |
| 证据优先 | ✅ 提示词明确要求引用原文 |
| AI自我质疑 | ✅ 提示词第四部分要求 |

+ **风险/改进**：工作流较为线性（抓取→分析→输出），缺少增量更新、批量处理、结果归档等功能。提示词3000字较长，可能增加token消耗和响应延迟，可考虑精简或分模块调用。系统目前是单篇分析，缺少跨文档对比能力。建议后续增加批量分析和历史对比功能。

## 5. 元认知视角评估与鼓励
+ **思维过程暴露程度**：较高。完整记录了从"完全不知道是什么"→问豆包→DeepSeek复核→注册Dify→找token→写提示词→试运行的完整学习路径，每一步都有心理状态记录（困惑、不自信、忐忑）。
+ **亮点鼓励**：
 1. 诚实记录了从零开始的困惑和不自信——"各种疑惑如同被打了一拳后看到的星星"，这种对知识差距的坦然承认本身就是元认知的起点，非常鼓励！
 2. 让AI在分析结束后"自我质疑"——这个设计把元认知从单向（AI分析人）升级为双向（AI也反思自己），很有创意。
 3. "三千字基本可以传达出内容大意"——用写小说的经验来估算提示词长度，这是跨领域类比思维的应用，很巧妙。
+ **可提升处**：提示词主要由DeepSeek代写，自己修改的痕迹较少。建议在试运行后记录"AI给出的提示词哪里好、哪里不符合我的意图、我改了什么"，这能更好地体现对AI输出的批判性审查。对同学作业的感慨（"同学们怎么这么强"）可以转化为具体的学习目标而非止步于情绪。

## 6. 困难总结
1. **完全不知道AI智能文档分析系统是什么**（认知性，已解决——问豆包+DeepSeek+老师解释）
2. **几乎所有工具都没听说过**（认知性/知识差距，已解决——逐步学习和注册）
3. **Dify免费额度较少**（技术性，已解决——自行注册DeepSeek获取API key）
4. **对元认知不太理解，不知道用什么标准评价文档**（认知性，已解决——复制课程介绍给DeepSeek辅助生成提示词）
5. **看到同学作业后缺乏自信**（情绪/认知性，部分解决——先写提示词跑一遍看看，用行动化解焦虑）
6. **提示词主要靠AI代写，自身修改较少**（认知性，未充分解决——试运行调试但未记录具体修改）
