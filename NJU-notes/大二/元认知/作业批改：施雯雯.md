# 作业批改：施雯雯
从需求开始，就有一种模糊感，文档多看不完是客观事实

> 挑出“有用”的文档，进行简单的总结记录，方便在有需要的时候查阅。
>

+ 怎么定义有用
+ AI怎么挑，技术方案是啥
+ 用什么策略总结
+ 查阅是指什么，从头看一遍，还是做一个有索引功能的东东

你仔细想想看是不是这样，真的从你的需求角度出发去做PBL

是可以延展出这些问题的，我们先不结果导向去思考为什么你的需求不够明确

我们就从具体的行为层面去给建议，下一次，是不是可以让AI补充一下你的需求

你先看一看，启发一下，然后再思考需求是不是可以补充和更细化，它对你后续实践是有帮助的

## 1. 完成度判定
+ 状态：部分完成
+ 依据：完成了从语雀 API 获取文档元数据、初步筛选分类、AI 评分排序的功能，并附有前端截图；但文档自述"就这样子太敷衍了"，评价体系和前端均有改进空间，系统整体处于初步原型阶段。

## 2. 系统需求清单
1. 从 NOVA 大量文档中挑出"有用"的文档，进行简单总结记录，方便有需要时查阅【基础需求，明确】
2. 文档分类：通知、课件、学生笔记、学生作业——通知和课件不交给 AI（需直接看），主要分析同学写的内容
3. AI 对文档进行评分，评估文档价值【初步设想：让 AI 自己评分】
4. 按类别再按分数排序展示
5. 做一个前端展示界面
6. 引入点赞数作为评价维度（点赞数多肯定有优点）【亮点：利用语雀社交数据辅助评价，比纯 AI 评分更客观】
7. 观察到"AI 更喜欢结构清晰的文档"——对 AI 评分偏差的初步觉察【亮点：开始批判性审视 AI 的评价倾向】

## 3. 搭建思路
+ 技术思路：拿着 token 先看能获得什么内容→获取元数据（id/slug/标题/作者/字数/介绍）→初步筛选（去掉字数为0的）→分类→AI 评分→按类别和分数排序→做前端展示。
+ 所用工具/平台：语雀 API（token 获取元数据）、AI（评分总结）、前端（让 AI 搭建，具体框架未明确说明）。

## 4. 技术评估：方案是否覆盖需求
+ 覆盖情况：需求1-5 已有基本实现（有截图为证），需求6（点赞数维度）为新增设想，需求7为观察发现；但整体处于原型阶段，评价体系不够完善。
+ 逐条对照：
 - 需求1（挑有用文档）：部分覆盖，通过分类+评分筛选，但"有用"的标准尚不明确
 - 需求2（文档分类）：覆盖，已按类别区分处理策略
 - 需求3（AI 评分）：覆盖，但评分标准不够稳定
 - 需求4（排序展示）：覆盖
 - 需求5（前端）：覆盖，有截图
 - 需求6（点赞数）：未实现，设想阶段
 - 需求7（AI 偏差觉察）：观察发现，未系统性解决
+ 风险/改进：AI 总结内容"有点空泛"（因为大家主题一样），评价体系需要改进；AI 评分存在偏好（喜欢结构清晰的文档），可能导致评分不公允；前端和评价体系均需迭代。

## 5. 元认知视角评估与鼓励
### 思维过程暴露程度：中
文档以较为口语化的方式展示了思考过程，如"先拿着token看看能获得什么内容""想一下怎么样让AI评价文档的价值……先让它自己评分试试看？""就这样子太敷衍了……再做个前端？"——呈现了边做边想的真实状态。对 AI 评分偏差的觉察（"AI 更喜欢结构清晰的"）是有价值的批判性观察。但整体反思深度有限，对"为什么空泛""如何改进评价标准"缺乏深入分析。

### 亮点鼓励
1. **务实的分类处理策略**：明确区分"通知和课件需要直接看，不交给 AI"——不盲目让 AI 处理所有内容，有合理的任务分配意识。
2. **对 AI 评价偏差的觉察**：观察到"AI 更喜欢结构清晰的文档"，这是对 AI 输出的批判性审视的开始，说明没有完全信任 AI 的评分结果。
3. **自我审视的诚实**：自述"就这样子太敷衍了"，对自身产出质量有清醒判断，不满足于初步成果——这种自我监控意识值得鼓励。

### 可提升处
+ "AI 总结内容有点空泛"是一个重要发现，但止步于观察，未深入分析原因（是否因为提示词设计不够具体？是否需要引入更多维度？）和解决方案。
+ 文档未描述遇到的困难（技术性/认知性），与作业要求"撰写文档描述搭建过程（遇到的困难、思考）"不完全匹配。
+ 技术方案描述较简略，未说明使用的具体 AI 模型、前端技术栈等。

## 6. 困难总结
+ **认知性**：AI 评分内容空泛（大家主题一样导致总结雷同）——已意识到，未解决
+ **认知性**：评价体系不够完善——已意识到，考虑引入点赞数但未实现
+ **认知性**：AI 评分有偏好（喜欢结构清晰的文档）——已观察到，未解决
+ **技术性**：一次获取上限100篇——已发现，未说明解决方案
+ **时间精力类**：自述"太敷衍了"——已意识到，有改进意愿但未进一步推进
