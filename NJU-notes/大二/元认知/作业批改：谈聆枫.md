# 作业批改：谈聆枫
我记得第一堂课，你是坐在我的最右手边的，为数不多我不认识，但是记住脸的...

看你的需求很有趣，你并不是告诉我们你希望实现什么，你是反过来的，你告诉我们你不希望做成什么样

最终，你把本属于人类的需求权力，丢给了AI（吐槽一下AI的输出，真烂）

这件事本身值得你去思考，因为 它很常见 。我经常会去问身边的学生，你有什么爱好，兴趣，想法，需求，其实很多人，自己都想不明白自己有什么需求，他们就每天默认的去做大家都在做的事情，然后，然后就没有然后了，似乎这样也挺好，反正也能活，还不至于退学，足够卷的话，GPA还不低

你没有具体描述实现过程，看起来是依靠Qoder和Codex的能力去替你大力出奇迹的完成了后续工作

好奇问问：你的详细的实施计划是怎么形成的，以及它具体的内容是什么？

## 1. 完成度判定
+ 状态：部分完成
+ 依据：需求思考和prompt设计较为深入，有详细的搭建过程日志和困难记录，但明确表示"DDL之前应该是看不到成果了"，系统尚未跑通。架构设计文档已完成，代码开发进行中但未产出可用成品。

## 2. 系统需求清单
1. 开发文档智能问答系统——将各类开发文档（华为/苹果开发者文档、Java/C++标准手册等）下载到语雀，用自然语言提问【亮点：定位小众/传统开发文档这个信息盲区】
2. AI自动联网下载文档并在语雀搭建（需用户确认内容和来源）【亮点：用户确认机制】
3. 严格按文档内容回答，文档中没有的可联网搜索但需在答案中体现
4. 联网内容经用户确认后保存到语雀生成新文档
5. 对话后支持内容蒸馏→上传语雀或保留本地，后续对话有记忆
6. 后台静默访问语雀，不影响用户其他操作
7. 最终产物为macOS app【亮点：明确的产品形态定位】
8. 原神千星奇域开发文档也纳入范围【亮点：趣味性扩展】

## 3. 搭建思路
+ 工具选择：QoderWork（在类真人操作上体感优于GPT和Claude），后转Codex进行代码开发。
+ 因语雀超级会员（299/年）才能获得personal access token，选择让AI在本地浏览器后台静默访问语雀dashboard。
+ 架构设计由旗舰模型完成，代码开发转移到Codex推进。
+ 按软件工程要求分四个阶段开发。

## 4. 技术评估：方案是否覆盖需求
| 需求 | 覆盖情况 |
| --- | --- |
| 开发文档下载到语雀 | ⚠️ 架构设计中，代码未完成 |
| 自然语言问答 | ⚠️ 架构设计中，代码未完成 |
| 联网搜索补充 | ⚠️ 设计中但未实现 |
| 内容蒸馏与记忆 | ⚠️ 设计中但未实现 |
| 后台静默访问语雀 | ⚠️ 方案可行但实现难度大（浏览器自动化） |
| macOS app | ❌ 未实现 |

+ **风险/改进**：后台静默访问语雀dashboard（浏览器自动化）技术复杂度高，不如申请token或用API来得稳定。分四阶段开发的软件工程思路正确，但需评估DDL内能否完成。建议先实现核心问答功能（MVP），macOS app封装可后续补充。

## 5. 元认知视角评估与鼓励
+ **思维过程暴露程度**：很高。完整展示了需求排除过程：课件重点提取→论文阅读器→开发文档问答，每一步都给出了"为什么放弃"的理由，这是典型的"穷尽+排除"策略，非常清晰。
+ **亮点鼓励**：
 1. 需求选型过程极其精彩——逐个排除不靠谱的需求并给出理由（论文galgame已烂大街、课件提取不能满足期末预习），这种"否定式收敛"思维非常成熟，值得鼓励！
 2. 对AI能力的分层认知很到位——"用高规格AI确定实施计划，用一般AI推进"的策略，以及对"较低性能模型依然会产生大量错误"的判断，说明对AI输出有批判性审查。
 3. 诚实面对"失焦/失控感"——承认在细节落实时"完全失焦，被牵着鼻子走"，这是极高水平的知识差距意识。
+ **可提升处**：需求设计过于宏大（macOS app + 浏览器自动化 + 联网搜索 + 记忆系统），在有限时间内难以全部落地。建议在需求阶段就做优先级排序，先做最小可用版本。"软件危机"的自嘲说明已经意识到范围蔓延问题，应在下一步主动收敛。

## 6. 困难总结
1. **默认AI模型知识停留在去年，疯狂查网页消耗token**（技术性，已解决——手动指定本地和云端模型）
2. **请求超时且无回退功能，污染上下文**（技术性，已解决——转移到Codex）
3. **QoderWork出现bug，打开工作目录自动退出登录**（技术性，已解决——发现不能两个AI agent同时操作同一工作目录，关掉重启）
4. **高低搭配模型策略仍产生大量错误需返工**（技术性/认知性，部分解决——认识到当前AI水平不足以让非专业工程师独立开发）
5. **开发周期不确定，预算一增再增（"软件危机"）**（认知性/项目管理类，未解决——需求范围过大）
6. **细节落实时失去掌控感，被AI牵着走**（认知性，已觉察——诚实承认但尚未找到应对策略）
7. **DDL前看不到成果**（时间精力类，未解决）
