# 作业批改：谷和平
你是整个班级当中最有经验，最有发言权的人，在这个任务上，你的Github项目也被最多人参考借鉴

AI对你的分析和我想和你说的事情其实是差不多的

就是我们一次次的用AI去创造一些新的东西，每一次创造的过程，你和我都能感受到一些东西

+ 可能是AI搓出来的那一堆屎山难以阅读和维护
+ 可能是过度消耗Token，或者完成任务的时间不可预估
+ 可能是最终还是要靠人去做一些事情，这个AI替代不了

那么，当下一个任务来临时，你我使用AI的技巧、策略、思路，和上一次比有什么变化

这种变化本身，我觉得可以认为正是AI时代我们学习的收获

 很认真的邀请你和我们一起分享这种改变，哪怕它很微小

## 1. 完成度判定
+ 状态：已完成
+ 依据：学生已有多个成熟项目（YuqueSyncPlatform、yuque2git、astrbot_plugin_yuque），文档完整回顾了从零基础到独立设计Agent架构的技术成长线，并系统阐述了搭建思路。系统已部署上线并有公开访问地址。

## 2. 系统需求清单
1. 稳定获取语雀知识库/文档信息（知识库列表、TOC、成员、作者、时间、字数、内容、阅读量等）
2. 实时获取文档更新信息（webhook优先，轮询兜底）
3. 文档处理与分析（下载到本地→AI分析/检索）
4. 增量更新感知与版本管理（git记录变更diff）
5. LLM判断diff是否有价值，有价值才推送【亮点：不是每次更新都推，而是AI判断价值后过滤】
6. 文档动态查看（谁更新了什么、谁评论了）
7. 查看某个人的所有文档（筛选CAC文档确认重要信息）
8. 通过IM平台（QQ、飞书）推送与查找文档
9. RAG检索 + 用户画像 + Agent智能体 + 长期记忆 + 智能推送
10. 迎新机器人自动审核入群（两阶段设计防提示词攻击）【亮点：两阶段隔离（research + answer）防prompt注入】
11. 改善语雀原有平台缺陷（搜索差、无法看某人所有文档、无法关注/订阅）

## 3. 搭建思路
+ 技术路线演变（五个阶段）：
 - 阶段一：语雀基础探索→Token/API批量获取→爬虫思路→webhook推送
 - 阶段二：Flask后端+webhook+MongoDB同步平台（YuqueSyncPlatform）
 - 阶段三：Web Agent探索（DOM提纯、浏览器操作能力）
 - 阶段四：yuque2git（git管理文档版本+LLM判断diff价值）→AstrBot选型→NovaBot（RAG+画像+推送）
 - 阶段五：迎新机器人（两阶段问答防注入）
+ 工具/平台：语雀API+webhook、Python、Flask、MongoDB、Git、AstrBot、LLM
+ 设计哲学：逐步迭代，每次解决前一个版本的痛点（邮件推送太多→git版本管理→IM推送→Agent化）

**风险/改进**：

+ 自己承认YuqueSyncPlatform"代码问题太多了，安全问题和潜在的逻辑、并发问题都很多"——这是诚实的自我评估，但也说明工程成熟度有待提升
+ yuque2git的邮件推送频率问题已通过LLM判断解决，但LLM判断的准确率和误判率未量化
+ 多个项目（SyncPlatform/yuque2git/NovaBot）之间存在功能重叠，可考虑统一架构

## 5. 元认知视角评估与鼓励
### 思维过程暴露程度：中等偏高
文档以"回顾"为主线，展示了从零基础到独立设计Agent的完整成长轨迹。AI生成的技术文档全景回顾比自己总结更详细，学生坦诚承认"有的细节我已经有些记不清了"。思路部分展示了"为什么做每个版本"的因果链路（前一个版本的痛点→下一个版本的改进），但反思深度可以更强。

### 亮点鼓励
1. **从零基础到独立设计Agent架构的完整成长轨迹**：从"准确来说我并没有掌握任何一门编程语言"到独立设计两阶段防注入架构，这条成长线本身就是最好的元认知教材——展示了"承认不懂→逐步学习→迭代改进"的真实过程。
2. **每次迭代都解决前一个版本的真实痛点**：邮件推送太多→git版本管理→LLM判断价值→IM推送→Agent化。这不是"为了做而做"，而是"用了发现不爽→改→再发现不爽→再改"的真实需求驱动迭代。这种"从使用体验中提取改进需求"的能力值得鼓励。
3. **诚实的自我评估**：明确承认YuqueSyncPlatform"代码问题太多了，安全和并发问题都很多"，不回避自己作品的缺陷——这是知识差距意识的体现。

### 可提升处
+ 文档以回顾为主，缺少当前作业的"新思考"——作业要求是"搭建思路+困难+思考"，但大部分内容是已有项目的回顾。可以补充"这次重新审视这些项目，我有什么新的认识"
+ AI生成的大段技术文档全景回顾占据了文档主体，自己的思考和反思相对被稀释——可以更多用自己的话总结，而非依赖AI输出
+ 缺少对"开发过程对AI依赖程度加深"的深度反思：提到"最开始纯手搓，之后再也没亲自敲过代码"，但没有深入讨论这种依赖的利弊和边界
