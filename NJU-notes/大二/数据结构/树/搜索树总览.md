# 搜索树总览（第七章 搜索）

## 一条主线
BST 用"左小右大"把二分查找搬进树里，查找代价 = 树高 h。
但插入顺序决定形状：有序插入退化成链表，h = O(n)。
于是问题变成：**如何让 h 恒为 O(log n)** —— 三种回答：

- **AVL**：每一步都盯紧（每个节点 `|bf| <= 1`），最严 → 树最矮、查询最快，但删除要修 O(log n) 次
- **红黑树**：差不多就行（只要求黑高一致，h <= `2*log2(n+1)`）→ 修改几乎不花钱（插入至多 2 旋）→ 工程标准（std::map/set、Linux CFS）
- **Splay**：过去就算了，未来补偿 —— 不维护任何平衡信息，访问后转到根，摊还 O(log n)，白送"最近访问最快"（缓存友好）

**线索树是正交的维度**：别人解决"树太高"，它解决"遍历要辅助空间"——n+1 个空链域拿来存中序前驱/后继，遍历免栈免递归。

## 对比表
| 树 | 平衡标准 | 查找 | 插入/删除 | 修复代价 | 额外字段 |
|---|---|---|---|---|---|
| BST | 无 | O(h)，最坏 O(n) | O(h) | - | 无 |
| AVL | 每点 `|bf|<=1` | O(log n)，最严 | O(log n) | 插入 1 次旋转；删除最坏 O(log n) 次 | 高度 |
| 红黑 | 黑高一致 | O(log n)，h<=`2log2(n+1)` | O(log n) | 插入至多 2 旋 + 变色；删除至多 3 旋 | 颜色位 |
| Splay | 无（摊还） | 摊还 O(log n)，单次可 O(n) | 摊还 O(log n) | 每次访问都旋转 | 父指针 |
| 线索树 | -（不谈平衡） | - | - | - | ltag/rtag |

## 记忆钩子
- AVL 四种失衡：LL→右旋、RR→左旋、LR→先左后右、RL→先右后左。失衡方向 = 插入路径最后两步，旋转 = 反方向掰回来；双旋本质是"先把折线掰成直线"
- 红黑树插入修复："叔红就变色上移，叔黑之字转一字，一字变黑转爷爷"
- Splay："一字转父，之字转己，转完自己上根"
- 线索树："左空存前驱，右空存后继，tag=1 是线索不是娃"
