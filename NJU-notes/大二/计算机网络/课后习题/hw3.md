
### 复习题

#### R1
* **网络层的分组名称**：数据报（Datagram，或网络层分组）。
* **路由器与链路层交换机的根本区别**：
  * **路由器**工作在网络层（第三层），它根据分组首部中的**网络层地址（如 IP 地址）**进行路由查找和转发决策。
  * **链路层交换机**工作在数据链路层（第二层），它根据数据帧首部中的**链路层地址（如 MAC 地址）**进行过滤和转发决策。

---

#### R2
* **数据平面的主要功能**：负责“**转发**”（Forwarding），即每台路由器的本地操作，决定到达该路由器某条输入链路的分组如何被转移、交换到该路由器的哪条输出链路。
* **控制平面的主要功能**：负责“**路由选择**”（Routing），即端到端的协调控制，决定分组从源主机到目的主机所经过的整条端到端网络路径。

---

#### R6
* **路由器的内部组件实现机制**：
  * **输入端口、输出端口、交换结构**：通常使用**专用硬件（如 ASIC、TCAM、硬件排队电路等）**实现。
    * *原因*：数据平面必须在线速（Line speed）下处理每个到达的分组，处理时延通常在纳秒到微秒级别，通用 CPU 和软件无法满足高吞吐率的要求。
  * **路由选择处理器**：通常使用**软件（运行在通用 CPU 上）**实现。
    * *原因*：控制平面执行复杂的路由选择协议（如 OSPF、BGP）、计算并维护路由表，对时间响应要求相对宽松（通常为毫秒到秒级），需要更高的灵活性与策略表达能力。
* **网络层的数据平面与控制平面**：
  * **数据平面**通常由**硬件**实现，以满足高带宽、低延迟的纳秒级线速转发需求；
  * **控制平面**通常由**软件**实现，以满足网络拓扑发现、复杂图算法计算及路由策略调整的灵活性需求。

* **分析**：
  * 应用数据负载：每块 $40$ 字节。
  * TCP 首部开销（无可选字段）：$20$ 字节。
  * IPv4 首部开销（无可选字段）：$20$ 字节。
* **每个数据报的开销**：
  $$\text{总首部开销} = 20\text{ 字节 (TCP)} + 20\text{ 字节 (IP)} = \mathbf{40\text{ 字节}}$$
* **总数据报大小**：
  $$\text{总大小} = 40\text{ 字节 (数据)} + 40\text{ 字节 (首部)} = 80\text{ 字节}$$
* **应用数据所占百分比**：
  $$\frac{40\text{ 字节}}{80\text{ 字节}} \times 100\% = \mathbf{50\%}$$

#### R30
* **首部字段对比**：
  * **完全相同的字段**：严格来说，只有**版本（Version）**字段在名称、位置和基本语义上保持一致（均为 4 比特）。
  * **功能对应但名称/格式变化的字段**：
    * IPv4 的“服务类型 (ToS)” $\rightarrow$ IPv6 的“业务类别 (Traffic Class)”。
    * IPv4 的“总长度 (Total Length)” $\rightarrow$ IPv6 的“有效载荷长度 (Payload Length)”。
    * IPv4 的“寿命 (TTL)” $\rightarrow$ IPv6 的“跳数限制 (Hop Limit)”。
    * IPv4 的“协议 (Protocol)” $\rightarrow$ IPv6 的“下一个首部 (Next Header)”。
    * IPv4 的“源/目的 IP 地址”（各 32 位） $\rightarrow$ IPv6 的“源/目的 IP 地址”（各 128 位）。
  * **IPv6 中移除的字段**：
    * 首部长度（IHL）：IPv6 首部固定为 40 字节，不再需要此字段。
    * 分片与重组字段（标识、标志、片偏移）：IPv6 不允许路由器在途中分片，改为端到端路径 MTU 发现机制或使用扩展首部。
    * 首部检验和（Checksum）：网络层不再进行差错校验，交由链路层和运输层完成，以提升处理效率。
    * 选项字段（Options）：移至扩展首部中。

#### P3
* **分析**：所有 $N$ 个分组在同一时刻到达 $N$ 个输入端口，且分别转发到 $N$ 个**不同的**输出端口。$D$ 为单分组传输时间。
  * **纵横式交换结构（Crossbar）**：由于目标输出端口互不冲突，纵横式交换机能建立 $N$ 条无干扰的交叉点通路，并行交换所有分组。因此最大输入排队时延为 $\mathbf{0}$。
  * **总线与内存交换结构**：共享总线/内存同一时刻只能串行处理一个分组。若 $N$ 个分组并发到达，第 1 个分组耗时 $0$ 开始传输，第 2 个分组等待 $D$，……，第 $N$ 个分组必须等待前面的 $N-1$ 个分组交换完成，最大输入排队时延为 $\mathbf{(N - 1)D}$。

#### P4
* **最小所需时隙数**：**3 个时隙**。
  * *调度过程*：
    * **时隙 1**：顶部输入队列发送发往 $X$ 的分组，中部输入队列发送发往 $Y$ 的分组（端口 $X, Y$ 并发）。
    * **时隙 2**：中部输入队列发送发往 $X$ 的分组，底部输入队列发送发往 $Y$ 的分组（端口 $X, Y$ 并发）。
    * **时隙 3**：底部输入队列发送发往 $Z$ 的分组。
  * 仅需 3 个时隙即可完成全部 5 个分组的传输。

  * *评估说明*：在“非空输入队列不空闲”且“调度器消除了 HOL 阻塞”的标准假设下，首个时隙必定可以同时发送 $X$ 和 $Y$，随后仍可保持高效流水线匹配，最多耗时 3 个时隙。若因极端队列到达顺序导致在某时隙发生严重输出冲突，最大需要 4 个时隙完成。

#### P19
* **a. 检测技术及评估**：
  * **技术方法**：在 NAT 外部捕获所有外发 IP 数据报并提取其 IP 首部中的**标识号（IP ID）**。由于每台主机发送分组时其 IP ID 是单调严格递增的，可以在时间维度上对这些 IP ID 序列进行聚类分析（Clustering）。不同的主机将对应各自独立演进、单调递增的连续数列轨迹。统计并发存在的独立递增轨迹的数量，即可推断 NAT 后面的活跃主机数量。
  * **评估**：在主机发包较为连续且网络丢包/乱序不严重的场景下，该技术准确度极高；但如果某些主机长期处于空闲状态、或两台主机偶然出现相近的初始随机 ID，则可能产生一定偏差。
* **b. 随机分配标识号下的有效性及评估**：
  * **结论**：**不能正常工作。**
  * **评估**：如果每台主机为每个 IP 分组完全随机选取 IP ID，则外部捕获到的 IP ID 序列在整个取值空间中呈现均匀无序的白噪声分布，无法形成可追踪的单调轨迹，聚类算法完全失效，因此无法区分不同主机。

### 复习题

#### R4
* **链路状态算法（LS，如 OSPF）**：
  * 采用**全局信息**，每台路由器通过向网络中所有路由器广播链路状态报文（洪泛），获取全网完整的拓扑结构和链路开销信息，然后独立运行 Dijkstra 算法计算最短路径。
  * 算法时间复杂度为 $O(|N|^2)$，收敛速度较快，不易产生路由环路，健壮性好。
* **距离矢量算法（DV，如 RIP/BGP）**：
  * 采用**分布式、异步迭代**方式。每个节点只与直接相连的邻居交换其当前的距离向量估计，基于 Bellman-Ford 方程迭代更新路由。
  * 算法易于实现，无需全局广播，但收敛较慢，且在链路开销增加时可能遭遇“无穷计数”问题和短暂的路由环路。

#### R6
* **结论**：**没有必要。**
* **原因**：因特网被划分为不同的自治系统（AS），每个 AS 在管理上由单一实体控制并拥有完全的内部自治权。每个 AS 可以根据自身网络的拓扑特征和管理需求，独立选用最适宜的 AS 内部路由协议（如 AS1 使用 OSPF，AS2 使用 RIP，AS3 使用 IS-IS）。各 AS 之间通过全球统一的 AS 间路由协议（BGP）进行跨自治系统的信息交换与路由聚合，内部协议的差异对外部网络完全透明。

#### R10
* **子网（Subnet）**：具有相同网络号的一组主机和路由器接口的集合。在子网内部，设备之间可以通过链路层网络（如交换机或集线器）直接通信，无需中继路由器介入。
* **前缀（Prefix）**：CIDR 记法中 IP 地址的网络部分（形式如 `a.b.c.d/x`），用于聚合表示一个包含多台主机的地址范围或多个子网的集合。

给定初始参数：$c(x, y)=4, c(x, z)=50, c(y, w)=1, c(z, w)=1, c(y, z)=3$。

* **a. 稳定时各路由器告知彼此的到 $x$ 的距离（在毒性逆转下）**：
  * 节点的最短路径选择：
    * $y$ 的最短路径是直连 $y-x$，开销为 $4$。
    * $w$ 的最短路径是 $w-y-x$，开销为 $1 + 4 = 5$（经由 $y$）。
    * $z$ 的最短路径是 $z-w-y-x$，开销为 $1 + 1 + 4 = 6$（经由 $w$）。
  * 毒性逆转通告（若节点通过某邻居去往目的地，则向该邻居通告距离为 $\infty$）：
    * **$y$ 通告给**：$x$ 为 $\infty$（因经由 $x$），$w$ 为 **$4$**，$z$ 为 **$4$**。
    * **$w$ 通告给**：$y$ 为 **$\infty$**（因经由 $y$），$z$ 为 **$5$**。
    * **$z$ 通告给**：$w$ 为 **$\infty$**（因经由 $w$），$y$ 为 **$6$**。

* **b. 当 $c(x, y)$ 增至 60 时，是否存在无穷计数问题及迭代评估**：
  * **结论**：**仍然存在无穷计数问题。**
  * **原因**：毒性逆转只能解决直接相邻两个节点之间的 2 节点环路（如 $y-w-y$），但无法防止涉及 3 个或更多节点构成的回路。当 $c(x, y)$ 剧增至 60 时：$w$ 向 $y$ 通告了 $\infty$，但 $z$ 向 $y$ 通告的距离为 6。因此 $y$ 会错误地认为可以经过 $z$ 到达 $x$（开销估算为 $c(y, z) + 6 = 3 + 6 = 9$），从而使流量在 $y \to z \to w \to y$ 的三节点环路中震荡递增。
  * **迭代次数评估**：环路中的开销在每次循环迭代中逐步累加，直至估计值超过经由直连链路 $c(x, z)=50$ 的开销为止。由于环路周长开销较小（单圈累加 3~5 左右），整个算法需要经历数十次迭代（约 **20~30 次**）才能最终跳出环路并稳定在通过 $z-x$ 链路的新状态。

* **c. 如何修改 $c(y, z)$ 避免无穷计数问题**：
  * 要消除该问题，需消除 $y$ 在绕行 $z$ 时的开销优势。只要将 $c(y, z)$ 增大到满足 $c(y, z) > c(y, w) + c(w, z) = 2$ 且大于 $50$ 的阈值（例如设置 **$c(y, z) \ge 60$**），或者物理上断开 $y$ 与 $z$ 之间的直连边，即可从根本上打破该环路，避免无穷计数。

#### P12
* **BGP 环路检测机制**：
  * BGP 是一种**路径向量（Path Vector）**协议。当 BGP 路由器通告一条路由时，它必须将自身所在的自治系统号（ASN）添加到该路由的 **`AS-PATH`** 属性列表中。
  * 当一台 BGP 路由器从邻居收到一条路由更新时，它首先检查 `AS-PATH` 列表。如果发现列表中已经包含了**其自身的 AS 号**，则表明该路由通告已经在网络中兜了一圈回到了本 AS，存在路由环路。
  * 路由器会**直接丢弃**包含自身 AS 号的路由通告，从而在控制平面彻底避免了环路的形成。

#### P13

* **数据流向机制**：
  * 虽然底层 BGP 策略基于商业协议不允许自治系统 B 经过桩网络 X 将流量透传给 Y（因为桩网络不充当过境中继），但运行在终端主机上的应用层程序可以绕过该限制。
  * 在 P2P 网络中，主机 X 作为一个活跃 Peer，首先在应用层建立一条面向主机 B 的连接并下载数据；随后，主机 X 建立第二条独立的 TCP 连接，将接收到的数据作为源节点主动上传给主机 Y。
  * 在底层网络层视角中，这仅被拆分为两次彼此完全合规的独立 IP 通信（从源到 X，以及从 X 到 Y），从而在应用层巧妙地实现了跨越未由 BGP 选定路径的端到端数据传输。

#### P20
* **结论**：**允许。BGP 完全支持 Z 实现这种策略。**
* **实现机制与原因**：
  * 在 BGP 中，路由的导出由各个自治系统完全自主决定。作为自治网络，Z 只需要在其 BGP 导出策略中，**仅向 Y 通告起源于 Z 本地的前缀路由**，而不向 Y 通告任何其他外部可达路径。
  * 根据商业对等惯例，X 与 Y 是对等关系，Y 与 Z 也是对等关系。对等网络之间只免费转发双方直属客户的流量，绝不替对方转售第三方对等流量。因此 Y 绝不会把来自对等方 X 的过境流量路由至对等方 Z。
  * 此外，Z 也可以在自身的 BGP 导入策略或边界防火墙中，依据源 IP 前缀对来自 X 的数据包配置丢弃规则，从而在数据平面确保自身不承担任何来自 X 的流量。
