# R5
1. **网络中间盒（防火墙与 NAT）友好性**：  
    大部分企业网、校园网和公共 Wi-Fi 的防火墙为了防止安全攻击，会默认拦截或严格限速未知的 UDP 流量；而 Web 常用的 TCP 80（HTTP）和 443（HTTPS）端口几乎全网无条件放行。
    
2. **充分复用现有的 Web 与 CDN 基础设施**：  
    现代流媒体将音视频切片为标准的 HTTP 报文，可以无缝借用全球极其成熟的 HTTP 缓存服务器和CDN进行边缘加速与分布式分发。
    
3. **应用层缓冲弱化了实时性冲突**：  
    视频点播与音频流通常具备数秒至数十秒的应用层播放缓冲，能够完全平滑 TCP 丢包重传带来的抖动，不再像纯交互式电话那样对丢包后的几十毫秒级延迟极度敏感。
# R8
1. **是否通过相同套接字？**
    - **不是**。它们通过**不同的套接字**传递。
2. **这两个套接字都具有端口 80 吗？**
    - **是的，这两个套接字在主机 C 上的本地端口都为 80。**
3. **讨论与解释**：
    - TCP 传输层解复用依赖于**四元组**：(源 IP, 源端口号, 目的 IP, 目的端口号)。
        
    - Web 服务器在主机 C 的端口 80 维持一个**监听套接字**，负责等待连接请求。
        
    - 当来自主机 A 和主机 B 的连接请求分别完成 TCP 三次握手后，主机 C 的操作系统内核会分别为它们生成一个全新的**已连接套接字**：
        - 套接字 1：{主机 A 的 IP, 主机 A 的临时端口, 主机 C 的 IP, 80}
        - 套接字 2：{主机 B 的 IP, 主机 B 的临时端口, 主机 C 的 IP, 80}
    - 尽管这两个套接字在主机 C 上的本地端口号完全相同（均为 80），但因为它们的源 IP（或源端口）不同，操作系统内核能够根据到来的报文段的完整四元组，精准地将数据解复用并定向投递到对应的套接字缓冲区。
