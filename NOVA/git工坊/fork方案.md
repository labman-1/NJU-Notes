
把第 6 页的“云端协作”精简为 **【开源社区的通用礼仪：Fork & PR】**：
* **Fork 是什么？** 相当于你在 GitHub 上把学长的项目“一键复印”了一份带回你自己家。
* **PR（Pull Request）是什么？** 你在自己复印的那份上写好了作业，敲门对学长说：“学长我写好了，请你审阅一下，帮我**合并（Merge）**进你的大本营吧！”

### 二、 现场 11 人实操的“双保险”行动指引（防止有人卡网）

#### 🟢 方案 A：标准 CLI 流（适合网络顺畅、手速快的同学）
指导大家按这 5 步走：
1. **网页端点 Fork：** 手机扫码或电脑打开你的仓库，右上角点击 **「Fork」** $\to$ 点击绿色 **「Create fork」**（此时项目已经到了他们自己名下）。
2. **Clone 自己的仓库：**
   ```bash
   git clone https://github.com/<他们自己的用户名>/nju-nova-git-playground.git
   ```
3. **本地新建文件：** 进入 `members` 文件夹，建一个 `自己的名字.md`，写一句话。
4. **提交并推送：**
   ```bash
   git add .
   git commit -m "add 名字"
   git push origin main
   ```
   *(因为推送到的是他们自己的 Fork 仓库，100% 不会报 403 权限错误，也不会跟别人冲突！)*
5. **发起 PR：** 回到网页端，GitHub 会自动弹出一个金黄色框 **「Compare & pull request」**，点进去直接点击 **「Create pull request」**。

#### 🟡 方案 B：急救“纯网页流”（适合终端网络卡死、密码记不得的同学）
如果现场有 2~3 位同学因为 Git 凭证、网络超时卡在 `git push` 上，**绝对不要走下去帮她配电脑**，立刻启动 B 计划：
* 对她说：“没关系，直接在刚才你 Fork 出来的网页上，点击 `Add file` $\to$ `Create new file`，在线打字，直接网页点 Commit，然后提 PR！”
* **效果：** 同样完成了 Fork & PR 的逻辑，所有人都能准时交差，绝不会有任何一个人掉队！

### 三、 现场最激动人心的“高潮收网”设计（最后 10 分钟）

这个环节是你作为主讲人的**高光时刻**，所有技术威信和极客仪式感都凝聚在这里：

1. **投屏 GitHub 仓库首页：** 
   * 你的电脑大屏幕切到你的仓库，点击顶部的 **「Pull requests」** 标签页。
2. **现场“报菜名”：**
   * 大屏幕上会不断弹出大家新提上来的 PR，比如 `feat: add zhangsan`、`feat: add lisi`。
   * 你在台上看着屏幕念：“好，我看到张三同学的 PR 已经进来了！李四也提上来了……”
3. **现场 Code Review 与一键合并：**
   * 当着所有人的面，点开其中一两个 PR，点开 `Files changed` 带大家看一眼：“看，Git 清清楚楚地标记出张三只新增了一个绿色文件，没有破坏任何其他人的代码。”
   * 点击绿色的大按钮：**「Merge pull request」** $\to$ **「Confirm merge」**！
4. **全场合体刷新：**
   * 把所有人的 PR 全部 Merge 掉。
   * 点击回到仓库首页的 `members/` 目录，按 `F5` 刷新大屏幕：**11 位同学的名字整整齐齐地并排出现在南大 NOVA 社的官方仓库里！**
   * 带头鼓掌：“恭喜大家，完成人生第一次真正的开源社区贡献！”
