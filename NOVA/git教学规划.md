#### 📌 Slide 2: 为什么需要 Git？（耗时 ~4 min）
* **核心意图：** 唤醒痛点，引出“快照（Snapshot）”概念。
* **大致怎么说：**
  > “大家看屏幕上这个段子：`final_v1`、`final_v2`、`绝对不改版`、`打死不改版`……写过论文、做过 PPT 或者改过代码的同学，肯定都干过这事吧？
  > 为什么传统的复制文件夹很糟糕？因为你不知道昨天到底改了哪一行，更没办法把两个人写的东西拼在一起。
  > Git 的本质，就是给你的项目装了一个**高精度的行车记录仪**。它不是把整个文件夹复制一遍，而是每次你打一个招呼，它就拍一张**历史快照**，任何时候你都能瞬间‘时空穿梭’回任意一个时刻。”

#### 📌 Slide 3: 核心模型 —— 三个工作区（耗时 ~5 min）
* **核心意图：** 这是全场**最重要的一页心智模型**，必须讲透比喻。
* **大致怎么说：**
  > “Git 为什么让很多人觉得玄学？是因为大家分不清文件到底在哪里。其实只要记住**超市买菜**这个比喻：
  > 1. **工作区（Working Directory）：** 就是你眼前的菜架子、书桌。你在这里写代码、删文件，随便折腾；
  > 2. **暂存区（Staging Area）：** 是你的**购物车**。写完一部分，你觉得‘这块代码挺满意’，就把它挑进购物车（`add`），但此时还没结账；
  > 3. **本地版本库（Local Repo）：** 是**收银台打出来的历史订单**。你点击结账（`commit`），盖章封箱，永久留档，谁也抹不掉。”
* **现场动作：** 指着屏幕上的三个方块，手势比划从左往右的流动。

#### 📌 Slide 4: 单机四大指令 + 现场带练（耗时 ~15 min）
* **核心意图：** 让他们敲出第一行命令，看到结果。
* **大致怎么说：**
  > “好，理论讲完，我们直接开干！大家打开终端（Git Bash 或终端）：
  > 1. 我们先挑一个干净的空文件夹，敲 `git init` —— 告诉电脑：从现在开始，这个文件夹由 Git 接管了！
  > 2. 新建一个 `test.txt` 随便写句话，敲 `git status` —— 盘点一下，Git 会用红字提醒你‘发现新商品，还没进购物车’。
  > 3. 敲 `git add .` —— 把东西扫进购物车。
  > 4. 敲 `git commit -m "第一次提交"` —— 结账封箱！
  > *（插入科普）：* 敲完没报错就是成功了，终端讲究‘沉默是金’。最后大家再敲一行 `git log --oneline`，看看是不是打印出了你的名字和历史记录！”
* **现场动作：** **你自己停下来**，把这页留在大屏幕上充当“小抄”，走下讲台转一圈，看谁终端报错了顺手提点一句。等大家都看到 `git log` 的输出了，再继续。

#### 📌 Slide 5: GitHub $\neq$ Git 与网络插曲【软休息 / 故事时间】（耗时 ~6 min）
* **核心意图：** 让他们手离开键盘，放松大脑，听故事学网络常识。
* **大致怎么说：**
  > “大家先停一下手，伸个懒腰，喝口水。接下来这 5 分钟大家不用碰键盘，听我聊个有意思的事。
  > 很多人以为 GitHub 就是 Git，其实完全不是：**Git 是你电脑里的单机软件，GitHub 只是微软家开的一个超大‘云端网盘’**。
  > 连 GitHub 为什么需要配置 SSH 密钥？就像非对称加密：公钥是挂在 GitHub 门上的一把**锁**，私钥是你电脑里的**钥匙**。全世界只有你的钥匙能开这把锁。
  > 
  > *（切入网络彩蛋）：* 前天我们社团有位同学遇到一个奇葩问题：在宿舍连校园网和热点，电脑死活注册不了 GitHub；结果关掉电脑、拿起手机切 5G 流量，秒解秒注册！为什么？
  > 揭秘一下：因为手机流量走的是现代的 **IPv6** 绿色通道，而电脑走的是拥挤且经常被干扰的 **IPv4** 老路，再加上人机验证码在电脑端风控极严……学计算机很有意思吧？一个小现象背后其实藏着网络分层的大学问。”

#### 📌 Slide 6: 云端协作：分支与推送（耗时 ~12 min）
* **核心意图：** 理解代码如何上传云端，以及分支的本质。
* **大致怎么说：**
  > “刚才我们在本地拍了快照，怎么把它发射到云端？敲一行 `git push`，把本地所有的快照同步给 GitHub，你在网页上刷新就能看到了。
  > 那怎么和别人合作？比如我们两个人在同一个项目里，他做登录，我做购物车，改串了怎么办？
  > 这就叫**分支（Branch）**。分支不是把项目完整复制了一份，它只是一张**随时会移动的便签贴纸**，指着当前最新的快照。大家各自在自己的便签上写，最后通过一个叫 **Pull Request（PR）** 的动作，请求负责人把两张便签的代码合在一起。”
* **现场动作：** 投屏演示一次 `git push`，打开网页端刷新，指给他们看“看，刚刚在黑框里敲的东西，现在全在网页上了”。

#### 📌 Slide 7: 偷懒方案：VSCode 原生 Git（耗时 ~5 min）
* **核心意图：** 降低实际使用的心智负担，给正向激励。
* **大致怎么说：**
  > “看到这里大家可能觉得：每次都要记命令好麻烦啊！
  > 别慌，在真正的开发中，除非特殊情况，我们日常其实很少全程手敲这几行命令。
  > 大家看我的屏幕：在 VSCode 左侧的‘源代码管理’里，改了文件会出现一个小加号，点一下就是 `git add`；在框里写句话按回车，就是 `git commit`；点右下角的同步，就是 `git push`。
  > **但是！你必须先懂命令行背后的‘三区模型’，你点鼠标的时候才不会心里发虚、出了冲突才懂得怎么自救。**”
