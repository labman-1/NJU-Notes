## 一、实现形式：单文件 PWA（论证）

- 手机是触发主战场 → 必须手机可达；桌面仅分析用 → 同一应用响应式适配，不做两端。
- 否决项：安卓原生（Kotlin 学习成本超 ZPD）、Electron/Tauri（桌面壳对 MVP 过重）、云服务（违反非目标，momentum 的数据同步 issue 是前车之鉴）。
- PWA = 一个产物 + GitHub Pages 零成本分发 + 离线可用（localStorage）。Hamon 已验证此路线：86KB 单 HTML，manifest 和 service worker 用 Blob URL 内嵌。
- HyperOS 3 注意：小米自带浏览器 PWA 支持弱，用 Edge/Chrome"添加到主屏幕"；保底方案 = 固定标签页。

## 二、功能规划（每条映射协议条款）

**MVP（W5-W6，共 ≤10h）：**
1. 链操作台：`[触发]` `[完成]` `[失败]` 三键 + 当前链长（页面唯一主角）+ 今日状态 —— 协议"C1 主链定义"
2. 判例裁决流：点"失败"强制弹窗二选一（判失败→清零重来 / 判允许→填判例文本永久记录）；判例库列表可查 —— 协议"下必为例"
3. 睡前评分：1/3/5 锚点 + 一句话；简单历史曲线 —— 协议 G1
4. 数据出口：导出/导入 JSON（一键下载、选择文件导入）—— 工程约束"备份责任在人"
5. PWA：图标 + 安装到主屏 + 离线打开

**v1.1（W7+，按失败记录解锁，每条需求须引用失败编号）：** 预约链倒计时（第一周先用手机自带时钟）；周视图（节点分布/评分曲线/失败三分类统计）。

**v2（数据驱动）：** 国策树可视化（先纸笔跑，国策 ≥5 个再做）；失败记录导出 + 复用 yuqueDocumentAnalysis 的 cluster.py 做 TF-IDF 聚类分析（技术复用闭环）。

## 三、技术栈（默认值 A，可换 B/C）

- **Vite 5 + TypeScript + vite-plugin-singlefile**：开发期有类型检查与 Vitest 单测，`vite build` 产物为单个 HTML（内联 JS/CSS）。TS 编译器 = "架构掌控"的机器护栏：不逐行读 AI 代码，但类型签名错就过不了编译。
- 无 UI 框架：沿用 Hamon 验证的"全局状态 + 每次变更全量落盘 + 从状态重渲染"模式（对 C++ 思维 = 全局 struct + autosave + 立即模式重绘）。
- 无 CSS 框架：手写 CSS 变量主题（约 100 行）。
- 备选 B：纯 vanilla JS 单文件（上手最快，无类型无测试护栏）；备选 C：React+TS（学现代前端，MVP 阶段过重）。

## 四、数据模型（架构宪法：四句话数据流）

1. 所有数据存于单个 localStorage key `ctdp_v1`（带版本号的 JSON）。
2. 每次用户操作 = 向 `events` 追加一条不可变事件（append-only，永不删除、不截断——events 是判例法的证据链，这是 Hamon 的 log 截断 300 条方案的刻意改进）+ 按规则更新派生字段（当前链长）。
3. 渲染永远从状态全量重算（无双向绑定、无增量同步）。
4. 清零 = 链长归零 + 记一条 fail 事件；历史事件永在。

```typescript
interface AppState {
  version: 1;
  chains: { [id: string]: { name: string; length: number } };   // length 为派生当前链长
  events: Array<{                                                 // 不可变证据链
    ts: number; chain?: string; type: 'trigger'|'done'|'fail'|'verdict'|'score'|'booking';
    verdictText?: string; score?: 1|2|3|4|5; note?: string;
  }>;
}
```
- schema 演进靠版本化 key（`ctdp_v2` 重开新档），不做迁移——Hamon 验证的防地狱方案。
- 纯函数层（链长计算、判例规则、评分统计）与 DOM 渲染完全分离，前者全覆盖单测。

## 五、审美（默认极简黑白）

暗色背景、系统字体栈、当前链长一个超大数字为唯一视觉主角、无动画（≤150ms 过渡除外）、无音效无庆祝效果。设计验收标准：打开 → 操作 → 30 秒内关闭。备选风格（军事指挥风 / 像素 Roguelike 风）成本高一个量级且有玩具化风险，v2 后仍可整体换肤（CSS 变量层隔离，换肤不动逻辑）。

## 六、工程流程与 AI 协作模式

- 每个功能开工前先写"规格卡"：数据流影响 + 验收清单（人工可跑）→ AI 生成 → `tsc` + `vitest` 双闸门 → 手动验收 → commit。
- 数据层（state.ts + logic/，预计 <250 行 TS）建议逐行读懂手写；UI 渲染层可放手给 AI（错了也只是显示问题，不伤数据）。
- 开发会话本身进 C1 链（协议自举条款）；每周日导出 JSON 备份（协议已定）。
- 仓库：GitHub 公开，GPL-3.0（与 momentum 一致，致敬理论原作者的开源声明），README 说明理论来源与协议映射。

## 七、里程碑（时间盒硬约束：每周 ≤5h，超时冻结两周）

- **W5（本周后半，5h）**：脚手架（Vite+TS+singlefile 配置一次到位）→ state.ts + logic 纯函数 + 单测 → 链操作台桌面可用。验收：触发/完成/失败清零全流程跑通，刷新状态保持，`vitest` 全绿。

## 八、风险与预案

| 风险 | 预案 |
|---|---|
