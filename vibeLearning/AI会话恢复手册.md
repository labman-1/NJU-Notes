# AI 会话恢复手册（上下文压缩后的记忆对齐流程）

> 制定 2026-10-27，来源：一次真实事故的复盘——上下文压缩丢失项目起点叙事（本项目从知乎原文理论诞生），
> AI 把继承当收敛、把旧闻当新闻，被用户纠正后按本流程完成恢复与对齐。
> 目的：把"发现记忆残缺 → 筛查恢复 → 对齐 → 顺承工作"变成可重复调用的程序，不依赖运气。

## 一、触发信号（何时启动本手册）

任一出现即启动，宁可误报：

1. **用户纠正一个"档案里早有记录"的事实**——尤其涉及项目起源、命名、既有裁决（本次实例：协议 09-28/10-07 早有血统注记，AI 却讲成"独立收敛"）。
2. **AI 叙事与文件内容矛盾**：AI 讲的历史、结论与协议、素材档等权威档案对不上。
3. **"重新发明"腔调**：把继承讲成发现、把旧闻讲成新闻、给已有机制另起新名。
4. **概念指称不确定**：用户用项目内术语（如"lv 升级"）而 AI 需要猜测其指代。
5. **用户直接点名**："对齐记忆 / 恢复上下文 / 你是不是忘了"。

## 二、恢复流程（五步，顺序执行）

1. **认错冻结**：承认记忆可能残缺，立即停止基于残缺记忆的进一步推论输出——错误框架会自我繁殖（本次"独立收敛"就是从残缺起点一路推出的自洽错误）。
2. **重建事实底座**：全量重读权威档案，不挑读。本项目的权威源与优先级：
   ① App JSON 导出（事件流，最高权威）；② 协议文件 `notes/元认知/CTDP启动配置-协议v1.md`；③ 素材档与周复盘（`notes/元认知/CTDP实践总结-素材档.md`）；④ 理论源 `自制力方法论总结.md`（原文本体=知乎专栏版 https://zhuanlan.zhihu.com/p/1930893902623245386 ，回答页 403 时改抓专栏版）。
3. **交叉筛查**：把记忆中的断言逐项对照档案，分三类——**档案证实 / 档案证伪 / 档案无载**。无载 ≠ 正确：向用户求证或明标不确定，不脑补。
4. **对齐落盘**：被证伪的认知，修正后必须写回文件（修档案漂移、补对照注、留认错记录）。落盘是对抗下一次压缩的唯一手段。
5. **恢复工作态**：从档案的"待裁/待核/观察"段落重建待办清单（不凭记忆），报告对齐结果，继续推进。

## 三、防再丢原则（为什么这次能恢复）

档案自足：关键血统、裁决、约定、待办全部写在文件里（协议修订记录、判例誊录、素材档时间线），压缩只能丢对话记忆，丢不了磁盘。
推论：**凡是要跨会话使用的结论，当场落盘**；只在对话里说过、没写进文件的，视同下次会不存在。

## 四、调用方式与限制

- **手动**：用户说"对齐记忆 / 跑恢复手册"。
- **半自动**：新会话触发第一节任一信号时，AI 主动读本手册并执行（workspace AGENTS.md 挂有指针，保证每个新会话都知道它存在）。
- **限制（诚实声明）**：若压缩丢掉的事实连档案里也没有，则不可恢复——这正是第三节原则存在的原因。
