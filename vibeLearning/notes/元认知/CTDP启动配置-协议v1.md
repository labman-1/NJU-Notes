# CTDP/RSIP 协议文本 v1.2

## 记录实体

QQ 小号消息流（大号 → 小号），append-only，带系统时间戳，可按前缀搜索回放。

## 链与格式

| 前缀 | 含义 |
|---|---|
| `[C1]` | 主链 1：触发 / 完成 / 失败 / 判例 |
| `[C1预约]` | C1 的辅助链（预约） |
| `[评分]` | 睡前评分（RSIP 根国策 1） |

消息格式（示例）：

```
[C1] 触发 15:10
[C1] #1 完成 16:12
[C1] #2 失败：中途刷手机约10分钟 → 裁决：判失败，计数归零
[C1] 判例#1：专注中查资料，离开屏幕≤3分钟属允许（永久生效）
[C1预约] 14:55        ← 发出后 15 分钟内必须发 [C1] 触发，失约按"下必为例"裁决
[评分] 3 平静：今天下午打了一个节点
```

## C1 主链定义

- 任务：**每日算法题（本业）**——满状态专注 60 分钟，读题→构思→实现→总结一体的深度专注，不凑题量
- 时长：满状态专注 60 分钟
- 触发扳机：发送 `[C1] 触发` + 手机翻面扣桌/离手
- 门槛：没把握保持满状态一小时就不许触发（不触发无任何损失）
- 计数：成功 = 消息序号 +1；失败 = 计数归零，从 #1 重来
- 周末条款：C1 不分工作日/周末，照常执行（算法不吃 DDL）；周末优先走预约链（无 DDL 日启动阻力天然更大，两极分化的高危场景）

## 辅助链（预约链）

- 信号：发送 `[C1预约]` + 手机时钟 15 分钟倒计时
- 义务：响铃后立即触发主链
- 失约：按"下必为例"二选一裁决

## 裁决规则（下必为例）

疑似违规只允许二选一，当场在小号登记：

1. 判失败：链清零，从 #1 重来；或
2. 判允许：写判例（编号永久生效，同类情况永久适用）

不允许"这次算了"。

规则：每天最多新增一条国策；国策失败 → 连同子节点熄灭（当前无树结构，单点熄灭重启）；健身为普通国策候补（"每周至少一次"最坏天气条款），待 G1/G2 稳定后上树。

G2 设计说明（决策记录）：勿扰防"被动唤起"（通知钩子），不可用时段防"主动刷"（应用打不开，比灰度更强的近端降值）。两者与经典护眼（全天常开）完全正交，无互斥。延期密码为纸枷锁，摩擦本身有价值但不作为依赖。观察层数据支持：周均屏幕 8h22m/天，使用峰值 20:00–24:00，问题窗口与 23:00 黑窗起点吻合；20:00–23:00 为无 DDL 晚间高危区，是 C1 晚间节点与预约链的主场。

## 侦查任务（W4 起启用，第一周禁用）

- 信号：`[C1侦查] 题号`——读一道题 + 想清楚思路即可记节点，5 分钟起步
- 进状态可顺势升级为正式触发；坚持不了零负担放弃，不计失败
- 用途：状态最差日子的降级通道，保链条的"日活"不断
